# 开发约定

## 版本号：每次功能改动后必须升

本扩展以**未打包方式**安装到 Chrome,浏览器不会自动读取磁盘上的新代码,
必须手动在 `chrome://extensions` 点刷新图标才会生效。因此版本号是用户确认
"代码确实更新了"的唯一依据,任何功能改动都必须提升版本号。

执行方式:

```bash
bash scripts/bump-version.sh [patch|minor|major]
```

脚本会同步更新两处标识:

| 位置 | 用途 |
| --- | --- |
| `manifest.json` 的 `version` | Chrome 扩展页显示的版本号 |
| `content.js` 的 build 标记 | 控制台日志 `Content script loaded [build X.Y.Z]` |

popup 标题下方的版本号由 `popup.js` 读取 manifest 自动显示,无需单独维护。

版本级别约定:

- `patch` —— 缺陷修复、样式调整(默认)
- `minor` —— 新功能
- `major` —— 不兼容的大改动

验证是否更新成功:

1. `chrome://extensions` → 找到本扩展 → 点刷新图标
2. 刷新 x.com 页面
3. 打开扩展 popup,确认标题下方版本号已变
4. 或看 Console 里的 `AI Twitter Filter - Content script loaded [build X.Y.Z]`

## 隐藏原因的语言

折叠横幅上的隐藏原因直接来自模型的 `reason` 字段,是**面向用户的文案**,
因此必须是简体中文。

模型会模仿提示词里的示例来产出 `reason`——示例语言即输出语言。
提示词写在 `filter-prompt.js` 的 `buildSystemPrompt` 里,其中显式要求:

- 原因必须用简体中文,不得含英文单词,不超过 6 个汉字
- 示例一律给中文("负面抱怨"、"政治煽动"、"垃圾推广" 等)

提示词是唯一决定该文案的地方,调整文案时只改这个模块,不要散落到别处。

### 非中文返回的兜底

小模型不一定遵守"用中文"的指令。`normalizeReason` 对不含中日韩汉字的
`reason` 一律判为无效(返回空串),由 `ui.js` 用统一的中文兜底文案
("已被 AI 过滤隐藏")顶上,保证横幅上不会出现中英混杂。

中英混排(如 "负面 toxic")含有汉字,会被保留——不因夹带个别英文词而丢弃
有效信息。

### 缓存必须按提示词版本分区

判定结果持久化在 `chrome.storage.session`,Service Worker 重启会恢复缓存。
若提示词变了(如要求原因改用中文)而缓存仍沿用旧版本,用户会继续看到
按旧提示词产出的结果。

因此 `filter-prompt.js` 导出 `PROMPT_VERSION`,提示词实质变化时递增;
`background.js` 持久化缓存时一并写入 `filterCacheVersion`,恢复缓存时版本
不一致则整体丢弃、重新判定。

## 分支

`main` 为唯一主线,功能开发完成后直接合入并在 `main` 上提交。
不再保留平行的功能分支——历史上曾因修复在 `main`、实际运行的是另一分支
的旧版,导致改动长时间无法生效。

## 改动后的检查流程

```bash
bash scripts/check-extension.sh
```

该脚本依次执行:各文件语法检查 → 专注模式单元测试 → popup 模块完整性测试
→ API 并发调度测试 → 无头浏览器行为测试 → 修复前后对比测试。

浏览器行为测试需要本机装有 Chrome,会自动拉起无头实例,结束后清理。

## 诊断线上问题

```bash
bash scripts/inspect-extension.sh
```

连到已开启远程调试的 Chrome(默认端口 9222),输出扩展的加载路径、
实际运行的代码版本与页面内的判定状态。

注意:该脚本刻意不访问 `chrome://extensions` 页面、也不调用
`chrome.developerPrivate`,那两类操作会触发 Chrome 反复弹出授权确认。
扩展的磁盘路径请在 `chrome://extensions` 页面手动查看。

## 判定期间的渲染约束

判定中的推文必须**完全不可见**且**高度不变**,两者缺一不可:

- 不可见:装插件的意义就是不让未过滤的内容先被读到
- 高度不变:推文尺寸一变,X 就会启用渐进渲染(推文分批冒出),
  同时虚拟列表会补拉推文,导致请求量成倍放大

实现上用 `visibility: hidden`(保留布局空间)而非 `display: none`(塌缩),
loading 指示器一律绝对定位,不得参与流式布局。
详见 `ui.js` 的 `markPending` 与 `styles.css` 的对应规则。
